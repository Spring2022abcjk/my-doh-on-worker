下面用精炼要点解释 worker.js 的架构与工作原理，力求“一眼看懂”：

## 顶层结构与入口
- 单文件 Cloudflare Worker，导出 `default.fetch(request, env)` 作为唯一入口。
- 运行时依据环境变量动态决定行为（DoH 代理 / DNS 聚合查询 / IP 地理查询 / 反向代理 / 静态 UI）。
- 逻辑是一个“多路复用路由器”：按 URL 路径和查询参数分派到不同处理分支。

## 关键环境变量
- `DOH`: 上游 DoH 服务主机（可写完整 URL，代码会提取 host）。
- `PATH` / `TOKEN`: 定义本 Worker 暴露的 DoH 路径 `/{PATH}`；`TOKEN` 还用作 `/ip-info` 访问授权。
- `URL302`: 未命中其它分支时执行 302 跳转。
- `URL`: 作为反代目标（支持逗号/换行/引号分隔的多地址随机选取；特殊值 `nginx` 输出示例页）。

## 请求分支总览（匹配顺序）
1. `OPTIONS`：返回标准 CORS 预检允许头。
2. `/{PATH}`：DoH 透传（函数 `DOHRequest`）
   - 支持三类：
     - `GET ?name=域名[&type=记录类型]`（JSON格式，优先 `dns-query`，失败再试 `resolve`）
     - `GET ?dns=Base64URL编码的二进制查询`（返回 `application/dns-message`）
     - `POST` 原始二进制 DNS 报文
3. `/ip-info?ip=...&token=...`：调用 `ip-api.com`（HTTP）再包装为 JSON（若配置了 `env.TOKEN` 则校验）。
4. `?doh=...&domain=...&type=all|A|AAAA|NS`：
   - 走多类型 JSON 聚合查询（函数 `queryDns` / `handleLocalDohRequest`）。
   - `type=all` 并发请求 A / AAAA / NS，合并为统一对象：`ipv4.records` / `ipv6.records` / `ns.records`。
   - 处理 NS 时同时收集 Answer 与 Authority，并把 SOA(type=6) 也并入总 Answer 便于前端展示。
   - 当 `doh` 指向当前站点域名时走 `handleLocalDohRequest`，避免自我嵌套递归。
5. 其余：
   - 若 `URL302` 存在 → 重定向。
   - 否则若 `URL` 存在 → 反向代理（函数 `代理URL`），路径拼接 + 随机后端。
   - 否则输出内置 HTML UI（函数 `HTML`）——前端直接调用上述接口进行交互。

## 核心辅助函数
- `queryDns(dohServer, domain, type)`：对同一个 DoH 端点尝试多套请求头（不同 Accept），解决部分服务 Content-Type 不规范；成功后返回 JSON。
- `DOHRequest(request)`：原样转发 DoH 请求，补充统一 CORS；若是 `name=` 查询强制 `Content-Type: application/json`。
- `handleLocalDohRequest(domain, type)`：避免本域 `?doh=currentHost` 导致 Worker 再请求自己，直接访问上游 `dns-query`。
- `代理URL(代理网址, 目标网址)`：解析多地址列表（借助 `整理`），随机选取，拼接原始请求路径与查询，发起 fetch 并返回，附加 `X-New-URL` 头用于调试。
- `HTML()`：内嵌 UI（Bootstrap），实现：
  - 切换多家公共 DoH 服务或自定义。
  - 一键 `type=all` 查询并分类显示 IPv4 / IPv6 / NS / 原始 JSON。
  - 根据硬编码“阻断 IP 列表”标记红色警示，并仍查询 `/ip-info` 获取 AS 信息。
- `nginx()`：返回示例欢迎页。

## 数据/响应形态
- 多类型聚合返回示例（精简）：  
  ```
  {
    Status, Answer:[...合并的A/AAAA/NS/SOA记录],
    ipv4:{records:[A记录数组]},
    ipv6:{records:[AAAA记录数组]},
    ns:{records:[NS/SOA记录数组]}
  }
  ```
- 单类型查询：直接透传上游 JSON（保持原始字段，如 Question / Answer / Authority / Additional）。
- 所有 JSON 分支都设置 `Access-Control-Allow-Origin: *` 方便浏览器前端跨域使用。

## 错误与健壮性
- DoH 转发失败：读取错误文本前 200 字符拼入消息。
- 多头尝试（`queryDns`）全部失败时抛出最后一次错误。
- `/ip-info`：封装下游错误 → 结构化 JSON（含 errorType、stack 第一行）。
- `name=` GET 无参数直接访问路径时返回 400（防直接浏览器点开）。

## 设计意图总结
- 单 Worker 将多用途（DoH 网关 + 聚合查询 + 简易反代 + UI + 地理查询）集中，降低部署与配置复杂度。
- 通过环境变量配置行为而非多份代码或多 Worker。
- 兼容不同 DoH 服务的 JSON / Header 差异，提升可用性。
- 聚合查询减少前端多次往返（一次请求获得 A/AAAA/NS）。
- 使用随机反代列表缓解单后端故障或做简单负载分摊。

## 扩展时的注意点（改动原则）
- 新增路由逻辑必须保持 CORS 一致性。
- 若再增加记录类型（例如 TXT、MX），可沿用 `type=all` 的并发模式与合并结构，前端需同步增选项卡。
- 若需要缓存，可在 `queryDns` 或聚合分支添加 KV/Cache 抽象，但要谨慎 TTL 与 SOA 信息的处理。
