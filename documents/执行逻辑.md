下面分三个阶段解释你问的情形：1) 代码上传后但无人访问；2) 第一次被访问（冷启动）；3) 第一次访问只是打开页面、尚未发起真正的 DNS 查询。

--------------------------------------------------
一、上传后、无人访问时
--------------------------------------------------
Cloudflare Workers 不会立即运行你的脚本。处于“静默”状态：
- 没有自动预执行、没有“启动钩子”。
- 顶层代码（文件最前面的 `let DoH = ...`、`const jsonDoH = ...`、`const dnsDoH = ...`、以及函数定义）尚未被真正“求值”执行在运行时 isolate 中，因为没请求触发。
- 不会向上游（cloudflare-dns.com 或 ip-api.com）发送任何网络请求。
- 没有内存和计费消耗（除部署元数据）。

--------------------------------------------------
二、第一次被访问（冷启动阶段）
--------------------------------------------------
当第一条请求到达（不论路径），Cloudflare 为该 Worker 创建一个新的 JavaScript 运行环境（isolate / V8 context）并按以下顺序发生：

1. 顶层求值
   - 执行变量初始化：`DoH = "cloudflare-dns.com"`，`jsonDoH = https://cloudflare-dns.com/resolve`，`dnsDoH = https://cloudflare-dns.com/dns-query`，`DoH路径 = "dns-query"`。
   - 所有函数（`fetch`, `queryDns`, `DOHRequest`, `HTML`, 等）被定义。

2. 进入 `default.fetch(request, env)`
   - 读取并解析请求 URL（获得 `path`, 查询参数）。
   - 如果 `env.DOH` 存在并且是完整 URL（含协议），会用正则提取 host 覆盖 `DoH` 变量。但注意：此时 `jsonDoH`、`dnsDoH` 常量已经在顶层用旧的初始值构造，不会随之改变（这是当前实现的一个行为特征）。
   - 计算 `DoH路径 = env.PATH || env.TOKEN || "dns-query"`；若包含斜杠，截取第一个斜杠后的段。
   - 然后按照路由分支依次判断：OPTIONS → `/{DoH路径}` → `/ip-info` → 有 `doh` 查询参数 → `URL302` → `URL` → 默认 HTML。

3. 返回响应
   - 本次请求对应哪个分支，就执行那部分逻辑并结束。全局变量留在 isolate 中，后续请求可复用（热启动）。

（后续再次请求通常直接复用同一 isolate，跳过顶层重新求值，除非平台回收或扩容产生新实例。）

--------------------------------------------------
三、第一次访问只是打开页面（根路径，无查询参数）
--------------------------------------------------
假设首次请求是浏览器访问根域名，比如 `https://你的worker.workers.dev/`，并且：
- 没有 `?doh=...` 查询参数
- 不是 `/{DoH路径}`（因为默认路径是 `/dns-query`）
- 不是 `/ip-info`
- 没配 `URL302`、也没配 `URL` 或 `URL='nginx'`

则执行逻辑是：
1. 顶层求值（如上第二部分第 1 步）。
2. 进入 `fetch`：
   - 路由检查前几个分支都不匹配。
   - 最终走 “fallback” 分支：调用 `HTML()`。
3. `HTML()` 只是构造一个巨大 HTML 字符串并返回（不会触发任何外部网络调用）。
4. 浏览器收到页面，前端脚本加载并渲染。
5. 此时还“没有开始查询 DNS 记录”：
   - 前端展示默认域名输入框（初始值 `www.google.com`）。
   - 没有自动调用 `?doh=...`；地理信息与 DNS 结果区域保持“等待查询”状态。
   - 如果用户没有点击“解析”按钮或“Get Json”，后台也不会向上游发起任何 DNS 请求。

（只有当用户在页面上点击“解析”按钮时，浏览器才会向同一个 Worker 发起 `GET ?doh=<选中的DoH>&domain=<域名>&type=all` 请求，Worker 才会调用 `queryDns` 并并发访问上游 DoH。）

--------------------------------------------------
补充：如果第一次访问的路径不同会怎样
--------------------------------------------------
- 首次访问 `/dns-query?name=example.com&type=A`：
  - 冷启动后直接进入 `DOHRequest`，尝试向上游 `dnsDoH` / `jsonDoH` 发请求（真实 DoH 查询发生）。
- 首次访问 `/ip-info?ip=8.8.8.8&token=<令牌>`：
  - 会发一个 HTTP 到 `ip-api.com` 获取地理信息。
- 首次访问 `/?doh=https%3A%2F%2Fdns.google%2Fresolve&domain=example.com&type=all`：
  - 会执行三次上游查询（A/AAAA/NS）并合并返回 JSON。
- 首次访问设置了 `env.URL302`：
  - 直接返回 302，不会执行 HTML 与查询逻辑。
- 首次访问设置了 `env.URL='nginx'`：
  - 返回 nginx 示例 HTML，不触发 DNS 与地理查询。

--------------------------------------------------
关键点回顾
--------------------------------------------------
- 上传后不运行：等待首个请求触发。
- 冷启动时顶层代码只执行一次；后面热请求复用状态。
- 首次纯浏览器访问根路径只返回 HTML，不做任何上游查询。
- 只有特定路径或查询参数才触发 DNS / 地理请求。
- `env.DOH` 只影响展示变量 `DoH`，不改变已固定的上游常量（除非你修改代码把构造移到 `fetch` 内）。
